# 🚢 决策树与集成学习实战（DT / RF / AdaBoost / GBDT / CatBoost）

**任务**：根据乘客信息（性别、年龄、舱位、票价等），预测其是否在沉船事故中幸存（二分类）
**目的**：通过同一个数据集，横向对比 **决策树**、**随机森林**、**AdaBoost**、**GBDT**、 **CatBoost** 五种算法，掌握从单模型到集成学习的演进思路。

## 🧭 五个算法简介

### 🌳 1. 决策树（Decision Tree）：AI 界的“二十问”游戏
🎯 **通俗解释**
想象你在玩“二十问”猜谜游戏：对方心里选定一个事物，你通过一连串“是/否”的问题不断缩小范围，直到锁定答案。决策树就是模仿这种分步判断的逻辑，把复杂任务拆成一条一条简单的判断规则，沿着分支走到最后的叶子节点，输出分类或者预测值。
⚙️ **核心原理**：决策树是自上而下、递归分裂构建出来的。
-**特征选择**：每次从全部特征里挑选最优分割条件，衡量纯度的常用指标有：ID3（信息增益）、C4.5(信息增益率（解决信息增益偏向取值多特征的问题）)、CART（基尼系数，固定采用二叉分裂）
-**数据分裂**：按照阈值把数据集切分成子集（ID3/C4.5 支持多分支，CART 只能二分）。对子集重复分裂过程，直到子集足够纯净，或者触发停止条件。
-**剪枝防过拟合（⚠️ 面试高频）**：预剪枝(训练时提前终止生长（如限制树深、节点最小样本量）);后剪枝(先生成完整大树，再从底层裁掉收益低的冗余分支)。
**注**：不加限制的决策树极易记住训练集噪声，泛化能力差。
💼 **应用场景**
金融风控：输出可解释的 IF-THEN 规则，满足监管对模型透明性的要求。
医疗辅助诊断：基于患者检查指标做疾病风险判断。
营销运营：客户分群，筛选高转化潜力用户。

---

### 🌲🌲 2. 随机森林（Random Forest）：群体智慧集成模型
🎯 **通俗解释**
单棵决策树很容易过拟合、结果不稳定。随机森林搭建了一大片独立的决策树；新样本送入后，每一棵树独立给出预测结果：分类任务采用多数投票，回归任务对结果取平均值，依靠集体判断得到更稳定可靠的结论。
⚙️ **核心原理**：双重随机性（Bagging + 特征随机子空间）
-**样本随机（Bootstrap 自助采样 / Bagging）**：每棵树通过有放回抽样单独构造训练集。约 37% 原始样本不会被采样到，称为 OOB（袋外数据），可用于评估模型效果。
-**节点特征随机**：在每个节点寻找最优分割时，不从全部特征搜索，而是随机选取一小部分特征子集进行筛选。
💡 核心机制：两套随机机制让每棵树学到差异化的规律，树之间相关性变低，集成之后有效降低模型方差，抵抗噪声带来的过拟合；训练过程天然支持并行计算，效率极高。
⚠️ **避坑提示**：增加树的数量不会造成过拟合，到达一定规模后模型效果趋于平稳。
💼 **应用场景**
生物医疗：基因特征、医学影像提取后的结构化特征做患病风险预测。
风控与电商：交易欺诈识别、用户购买偏好预测。
工业运维：基于历史监测数据预测设备、构件损耗劣化程度。

### 📈 3. AdaBoost（Adaptive Boosting）：知错能改的“错题本”
🎯 **通俗解释**
AdaBoost 一轮轮训练弱模型。第一轮做完一套习题，标记出错题；下一轮提高错题的权重，强制模型重点攻克这些容易分错的样本。
每训练完一个弱模型，会根据它的表现分配话语权(投票权)。最后把所有弱模型加权融合，得到整体预测结果。
⚙️ **核心原理**
-**串行训练**：区别于随机森林的并行独立训练，模型逐个生成，后一个依赖前一个的结果。
-**更新样本权重**：每一轮提升错分样本的权重，降低正确样本权重，迫使后续模型关注难样本。
-**加权投票**：不是均等投票，误差越小效果更好的弱分类器拥有更高决策权重。
⚠️ **致命弱点**：对噪声、离群点非常敏感。异常样本会持续获得高权重，模型过度去拟合少数噪声点，带来严重过拟合。
💼 **应用场景**
历史经典落地：早期人脸检测 Viola-Jones 算法就是 AdaBoost 的代表。
现状：原生 AdaBoost 现在工业落地很少，更多用来理解 Boosting 思想，适合干净、噪声少的数据，面试作为 Boosting 入门案例。

### 🌲 4. GBDT（Gradient Boosting Decision Tree）：站在巨人肩膀上拟合负梯度
🎯 **通俗解释**
和 AdaBoost 修改样本权重的思路不同，GBDT 采用接力修正误差的方式。
拿回归举例：第一棵树预测得到 80，和真实值 100 相差 20，这个差值叫残差。第二棵树不去直接预测 100，而是专门学习这个误差；多棵树的结果累加起来逼近真实值。
⚠️ **严谨补充**：回归任务误差刚好等于负梯度；分类任务拟合的是损失函数的负梯度，不再是简单直观的残差。
⚙️ **核心原理**
-**拟合负梯度**：每一轮新树拟合损失函数的负梯度，不断修正前面模型整体的偏差。
-**学习率（Shrinkage 收缩）**：每一棵树的贡献会乘以一个小于 1 的系数，降低单棵树的影响力；用更多数量的弱树逐步修正，有效控制过拟合。
-**调参黄金法则**：学习率越小，通常需要更多决策树配合。
⚠️ **调参痛点**：原生 GBDT 对超参数敏感，树深、学习率、迭代次数需要精细搭配以控制过拟合风险（注：树模型不存在神经网络那种“局部最优”问题）。
💼 **应用场景**
在深度学习普及前，GBDT 是互联网广告 CTR 预估、搜索推荐排序、金融风控结构化数据的主流模型；现在仍是传统业务强大的基线模型，后续衍生出 XGBoost、LightGBM 这些工程优化版本。

---

### 🐱 5. CatBoost（Categorical Boosting）：把类别特征“一键看懂”
🎯 **通俗解释**
XGBoost 和 LightGBM 本质上都是处理数字的。遇到“城市”、“性别”这种类别特征时，必须手动做 One-Hot 或 Label Encoding，非常繁琐。CatBoost 就像是一个“懂业务”的专家，它能直接“看懂”类别特征，自动帮你处理，而且还能有效避免数据泄露（Target Leakage）。
⚙️ **核心原理**
- **原生类别特征自动编码**：内部使用基于统计的方法（Ordered Target Statistics，有序目标统计），自动将类别特征转化为数值，并自动处理缺失值。
- **Ordered Boosting（有序提升）**：训练时模拟时间序列的顺序，确保当前样本在计算统计量时，只使用它“之前”的样本信息，有效防止目标泄露（Target Leakage）、降低训练偏差。
- **基线效果优秀 & 对称树结构**：默认参数通常就能跑出相当不错的效果（复杂数据集依然需要调参控制过拟合）；内置的对称树结构让推理（预测）速度极快。
**优点**：
- 类别特征处理能力强，开箱即用
- 防止 target leakage 的机制设计得很完整
- 在很多结构化数据上效果稳定
**缺点**：
- 对纯数值数据集来说，优势可能不如 XGBoost / LightGBM 那么突出
- 训练参数也需要一定理解
💼 **应用场景**
高类别特征数据：如电商数据（海量商品ID、用户ID、类目）、用户行为日志等。
快速 Baseline：当拿到一份包含大量文本类别的新数据，不想花几天时间做特征工程时，直接扔给 CatBoost，往往会有惊喜。

## 📊 五种算法横向对比

| 维度 | 决策树 | 随机森林 | AdaBoost | GBDT | CatBoost |
|------|--------|----------|----------|------|----------|
| 训练方式 | 单模型 | 并行独立 | 串行 | 串行 | 串行 |
| 集成思想 | — | Bagging（样本+特征随机） | 样本权重重分配 | 拟合负梯度 | 有序提升+原生类别处理 |
| 对噪声敏感度 | 高 | 低 | **极高** | 中 | 较低 |
| 可解释性 | ★★★★★ | ★★★ | ★★★ | ★★★ | ★★★ |
| 训练速度 | 快 | 快（可并行） | 慢（串行） | 慢（串行） | 快（多线程/多GPU） |
| 过拟合风险 | 高（需剪枝） | 低 | 高（噪声下） | 中（需调参） | 中（需控制 depth） |
| 典型场景 | 监管可解释 | 稳健基线 | 干净数据/教学 | 结构化数据王者 | 高类别特征数据 |





**项目总结**：Titanic — 决策树 / 随机森林 / AdaBoost / GBDT / CatBoost 集成学习实战

1. 项目背景与目标
-业务问题：根据乘客信息预测其是否在泰坦尼克号沉船事故中幸存
-任务类型：二分类问题
-项目目的：
--练习决策树、随机森林、AdaBoost、GBDT、CatBoost 五种算法
--理解单树 vs Bagging vs Boosting 的区别
--学会在同一数据集上做统一预处理、统一评估、统一对比

2. 数据概况
-数据集结构
数据集	                  行数	       说明
train.csv                891          训练集，含标签 Survived
test.csv                 418          测试集，无标签
gender_submission.csv    418          官方样例提交文件
-特征主要包括
数值特征：Age, Fare, SibSp, Parch, Pclass
类别特征：Sex, Embarked, Cabin, Ticket, Name
-数据特点
Survived 比例大约 38%
存在缺失值：Age 缺失较多；Embarked 少量缺失；Cabin 缺失非常严重
特征类型混合，适合树模型和集成模型练习

3. EDA 结论
-标签分布：幸存率约 38%；类别不平衡不算特别严重，但仍需关注
-重要观察：
性别 Sex 对幸存率影响非常大；
舱位等级 Pclass 与幸存率强相关；
票价 Fare、家庭规模 SibSp / Parch 也有明显影响；
Cabin 缺失太多，直接使用价值有限
-EDA 的意义
这一步建立了对数据的直觉：哪些特征重要；哪些特征可能要做衍生；哪些特征需要清理或丢弃

4. 数据清洗
-处理策略
删除 Cabin：缺失率太高；原始信息噪声大，直接保留意义不大
填充 Age：用中位数填充；中位数比均值更稳健，适合有离群值的场景
填充 Embarked：用众数填充；因为缺失很少，简单可靠
填充 Fare：测试集中有少量缺失，用中位数处理
-为什么这样做
Titanic 是经典的结构化数据分类任务，模型对缺失值比较敏感。
先做好简单稳健的清洗，能让后续模型比较更公平。

5. 特征工程（这个项目里很关键的一步）
做了哪些衍生特征
-1）Title
从 Name 中提取称呼：Mr，Mrs，Miss，Master，Rare
意义：称呼能间接反映年龄、性别、社会身份；在 Titanic 这种数据里非常有效
-2）FamilySize：FamilySize = SibSp + Parch + 1（表示家庭总人数）
意义：家庭人数可能影响逃生行为；过大或过小的家庭规模都可能影响幸存率
-3）IsAlone
是否独自一人：IsAlone = (FamilySize == 1)
意义：独自乘客和家庭乘客的生存模式可能不同
-4）FareBin：把票价分箱处理。
意义：票价原始值分布偏斜；分箱后更适合树模型学习
-5）AgeBin：把年龄分成几个区间。
意义：年龄对幸存率不是完全线性的；分段之后更容易体现“儿童优先”等规律

6. 模型构建思路（这次项目核心不是只做一个模型，而是做五个模型对比）
-1. 决策树：单模型基线；优点是可解释性强；缺点是容易过拟合
-2. 随机森林：Bagging 思想；多棵树投票，降低方差；一般比单树更稳
-3. AdaBoost：Boosting 思想；逐轮关注错分样本；对噪声更敏感，但有时能比单树更强
-4. GBDT：也是 Boosting 思路；每轮拟合前一轮的残差/负梯度；在结构化数据上通常表现很强
-5. CatBoost：对类别特征天然友好；有序目标统计防止数据泄漏；基线效果好，推理快

7. 建模流程
-统一预处理（为了公平对比，五个模型共用同一套前处理）:
数值特征(中位数填充)；类别特征(One-Hot 编码)；Pipeline + ColumnTransformer 统一封装
-验证方式（采用两种评估方式）:
80/20 留出验证集(直观看一次训练效果)；
5 折分层交叉验证(更稳健；更适合 Titanic 这种小数据集)

8. 模型表现总结
-验证结果趋势（这次跑出来的结果大致如下）:
模型	  表现
决策树    最弱，容易过拟合
随机森林  明显优于单树，比较稳定
AdaBoost  有提升，但不一定最优
GBDT      综合表现很好
CatBoost  类别特征利用充分，表现亮眼（本项目最终最优）
-结果合理性(这完全符合机器学习常识)：
单棵决策树 容易学得太死；
随机森林 通过投票更稳；
AdaBoost 在干净数据上有效，但对噪声敏感；
GBDT 在结构化表格数据上通常非常强；
CatBoost 对类别特征友好，在 Titanic 这种类别特征明显的数据上有优势

9. 评价指标
-这个项目用的指标主要是：
Accuracy：最直观，但不是唯一标准
ROC-AUC：更适合看排序能力
Confusion Matrix：看错分情况
Classification Report：看 precision / recall / F1
-为什么不用只看准确率
Titanic 虽然类别不算特别极端不平衡，但准确率单独看还是不够全面。
特别是分类任务，模型可能在整体准确率上不错，但对少数类预测不够好。

10. 最终提交
用最佳模型对测试集进行预测
生成 submission.csv

**可以继续优化的方向**
-更细的超参数调优：尤其是 GBDT 、随机森林和 CatBoost
-更正式的特征选择：比如尝试 Permutation Importance
-更规范的交叉验证管道：让 FareBin、AgeBin 的处理完全在 fold 内完成
